# 发布流程

仓库包含 Windows-only 的 GitHub Actions Release workflow。

正式发布前，需要在 GitHub Actions Repository Secrets 中配置：

```text
TAURI_SIGNING_PRIVATE_KEY
TAURI_SIGNING_PRIVATE_KEY_PASSWORD
```

Updater 签名私钥绝对不能提交到 Git 仓库。

推荐发布流程：

1. 修改 Tauri 配置中的应用版本。

修改 Cargo.toml 文件和 package.json 版本号。

2. 在本地执行完整验证：

   ```powershell
   bun install --frozen-lockfile
   bun run build
   cd src-tauri
   cargo check
   cd ..
   bun tauri build
   ```

3. 提交 Release 相关修改。
4. 创建并推送与应用版本一致的 Git Tag，例如：

   ```powershell
   git tag --list
   git push origin --delete v0.1.0
   git tag -d v.1.0
   
   git tag v0.1.0
   git push origin v0.1.0
   ```

5. GitHub Actions 构建 Windows 安装包和 Updater 产物。
6. GitHub Actions 创建 Draft GitHub Release。
7. 检查生成的安装包、Updater `.sig` 签名文件和 `latest.json`。
8. 在发布前实际测试安装包。
9. 确认无误后 Publish Draft Release。
10. Release 正式发布后，客户端才能通过 Updater endpoint 检测到该版本。

应用版本和 Git Tag 应保持一致，例如：

```text
应用版本：0.1.0
Git Tag： v0.1.0
```

未进行 Windows Authenticode 代码签名的程序可能触发 Microsoft Defender SmartScreen 或信誉警告。正式面向更广泛用户分发时，建议后续增加 Windows 代码签名证书。

Tauri Updater 签名用于验证更新包真实性，**不等同于** Windows Authenticode 代码签名。
